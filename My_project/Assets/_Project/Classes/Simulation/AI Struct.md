AI Struct.md

Минимальный каркас:
LocalSimulationContext (readonly struct): ссылки на GameStateService, идентификатор активной системы/снэпшот, float dt, int day, буферы (шоты, события). Без аллокаций.
LocalSimulationPipeline : держит список стадий List<ISimulationStage>, Name = "Local", RunStep(in ctx) проходит стадии по порядку.
Стадии по плану (можно пустые заглушки):
LocalInputStage — собирает команды игрока/триггеры (пока noop).
LocalPerceptionStage — строит видимый мир для юнитов (пока noop).
LocalAiStage — принятие решений (noop).
LocalMovementStage — движение (noop).
LocalInteractionStage — стыковка/ремонт (noop).
LocalCombatStage — бой (noop).
LocalEventsStage — события (noop).
LocalSnapshotStage — сбор среза для рендера (noop или заполняет пустой снапшот).
Проведение через SimulationRootController: RunLocal создаёт LocalSimulationContext и вызывает LocalSimulationPipeline.RunStep. Контекст можно собрать из SimulationStepContext + активной системы (например, GetSelectedSystem()).

Чтобы не плодить мусор: стадиям передавать in LocalSimulationContext; пайплайн — один список стадий (классы-заглушки без аллокаций внутри). Логи — по флагу.

## Что делает 01_LocalInputStage
- Забирает пользовательские приказы и события UI до начала симуляции (выбор цели, приказ патруля, пауза).
- Конвертирует их в структуры типа `PlayerOrder` (тип команды + параметры) и кладёт в очередь `SystemState.PendingPlayerOrders`.
- Обновляет глобальные флаги (смена активной системы, изменение скорости времени), если от игрока пришёл такой сигнал.
- Не двигает объекты и не считает логику — только собирает входные данные, которые потом используют Perception/Ai/Movement.

## Что делает 02_LocalPerceptionStage
- Читает активную систему из `LocalSimulationContext`, собирает текущие позиции/состояния кораблей, планет и событий.
- Готовит данные для ИИ: создаёт или обновляет `ShipAgentState` в `SystemState`, чтобы у каждого корабля был UID, последняя позиция, цель патруля, таймеры.
- Сканирует окружение: отмечает опасные зоны, интересные точки (станции, события), свободные коридоры для патруля. Пока патруль простой, достаточно ограничиться списком доступных точек в радиусе.
- Сбрасывает устаревшие данные: если корабль пропал, удаляет его агент из `SystemState`, очищает очереди команд для отсутствующих сущностей.
- Заполняет временные буферы: например, `SystemState.VisibleShips` или `PerceptionBuffer`, который потом прочитает `LocalAiStage`.
- Никаких решений не принимает, только синхронизирует «живой мир» с данными для логики. Этот шаг запускается каждый тик, чтобы `LocalAiStage` всегда работал на свежих координатах и наблюдениях.

## Что делает 03_LocalAiStage
- Из LocalSimulationContext достаёт GameState + ссылку на активную систему (`StarSys? ActiveSystem`). Через неё и получаем `SystemState`.
- Перцепция к этому моменту уже заполнила в `SystemState` актуальные списки (`ShipAgents`, `VisibleShips`, другие буферы), а `01_InputStage` набила очередь `PendingPlayerOrders`.
- Читает очереди и буферы стейта напрямую (в памяти) — без аллокаций: проход по `ShipAgents`, peek из `PendingPlayerOrders`.
- Для каждого корабля (или другого агента) решает, какую задачу выдать: патруль, перемещение, атака и т.д. Сейчас — только патруль.
- Генерирует команды (`MoveToPosition`, `Patrol`, позже `Attack`) и складывает их в `SystemState.PendingShipCommands`.
- Обновляет состояние агента (`ShipAgentState`): цель, статус команды, таймеры.
- Отрабатывает приказы игрока: если игрок указал новую точку патруля для корабля, ИИ должен уважить этот приказ и перезаписать цель.
- Не валит корабли напрямую — только выдаёт решения и очереди команд, которые затем исполняет `LocalMovementStage`.

## Что делает 04_LocalMovementStage
- Считывает очередь команд (`PendingShipCommands`) и для каждой выполняет фактическое движение/позиционирование в плоскости системы.
- Реализует примитивы типа `MoveToPosition`: двигает корабль в сторону цели, проверяет расстояние, обновляет `Ship.Position`/`Rotation`.
- По завершении команды уведомляет Ai/Events (помечает команду как `Completed`, убирает её из очереди, при необходимости пушит событие).
- Следит за столкновениями/ограничениями: чтобы корабли не выходили за радиус системы, не заходили в “мертвые зоны” (если они есть).
- Не принимает решений — только механически исполняет то, что запланировал AI.

## Что делает 05_LocalInteractionStage
- Обрабатывает «мирные» взаимодействия: стыковки, ремонт, передача ресурсов, посадки на станции.
- Проверяет, есть ли активные запросы (`InteractionRequests`) и применяет их (например, при стыковке корабль привязывается к станции, снимаются ресурсы).
- Обновляет состояние объектов (здоровье после ремонта, запасы топлива) и формирует события (`InteractionCompleted`), чтобы UI/AI знали об изменениях.

## Что делает 06_LocalCombatStage
- Отвечает за боевые расчеты внутри активной системы: проверки дистанций, урон, состояния оружия.
- Берёт из `SystemState` списки активных сражений/оружия и высчитывает попадания, расход боеприпасов, уничтожения.
- Генерирует события (`ShipDestroyed`, `DamageTaken`), чтобы Movement/Events/AI корректно отреагировали.

## Что делает 07_LocalEventsStage
- Консолидирует все события, произошедшие на стадиях выше (боевые, взаимодействия, выполнение приказов).
- Упаковывает их в единый список/очередь (`SystemState.StepEvents`), который потом читает UI или глобальная логика.
- Может запускать скрипты или реакцию NPC на определенные события.

## Что делает 08_LocalSnapshotStage
- Снимает визуальный срез состояния системы для рендера (`SystemMapRenderer`, UI).
- Пишет в снапшоты данные по кораблям, эффектам, чтобы между тиками можно было интерполировать (мы уже делаем это для кораблей).
- Очистит временные буферы и подготовит сцену к следующему шагу.
