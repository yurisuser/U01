# ИИ симуляции

Рабочая область нового каркаса поведения агентов. Существующий код ИИ пока не переносится и не определяет устройство нового каркаса.

## Базовая цепочка

```text
Базовое назначение
  → текущий приказ
  → корневое поведение приказа
  → составные поведения необходимой глубины
  → исполняемая задача
  → Local / Global Simulation
  → результат задачи и события мира
  → активное поведение продолжает работу или меняет решение
```

Обязательного общего объекта `План` в каркасе нет. Поведение может построить и хранить план, если он действительно нужен, либо выбирать следующую задачу по мере исполнения.

## Базовые понятия

### Базовое назначение

Постоянная обязанность, задаваемая при создании или назначении агента.

```text
Свободный торговец в регионе
Охранять станцию
Патрулировать сектор
```

После завершения временного приказа агент может вернуться к базовому назначению.

### Приказ

Установка верхнего уровня: чем агент должен заниматься сейчас и в каких рамках.

```text
Торговать в секторе
Торговать в радиусе 25 световых лет
Охранять станцию
Исследовать область
Атаковать цель
```

### Составное поведение

Логика, которая ещё должна принимать решения. Она может выбирать другие составные поведения или выдавать исполняемые задачи.

```text
Торговать
Выполнить сделку
Исследовать область
Атаковать цель
```

Количество уровней составных поведений заранее не фиксируется.

### Исполняемая задача

Запрос, который `Simulation` умеет принять, выполнять и завершить понятным результатом.

```text
Лететь к объекту
Стыковаться
Купить товар
Продать товар
Сканировать объект
```

Исполняемая задача не обязана завершаться за один тик. Слово «атомарная» для таких задач не используется.

## Жизненный цикл исполняемой задачи

У задачи разделяются три разные сущности:

```text
Описание задачи:
  неизменяемый запрос ИИ с конкретными параметрами

Состояние исполнения:
  изменяемые служебные данные, которыми владеет Simulation

Результат:
  неизменяемое сообщение о том, чем закончилось выполнение
```

Общие активные состояния задачи:

```text
Ожидает запуска → Выполняется → Отменяется
```

Конечный исход:

```text
Успешно
Ошибка
Отменена
Отклонена
```

`Отклонена` означает, что `Simulation` не приняла задачу к выполнению. `Ошибка` означает, что задача была принята, но завершить её по контракту не удалось.

Универсального состояния «выполнено частично» нет. Частичный объём является данными конкретного результата. Например, задача «купить до 100 единиц» может успешно завершиться с результатом «куплено 60», если такой исход разрешён её контрактом.

Исполнитель сообщает результат, но не решает, как восстанавливаться после ошибки. Продолжить, повторить, выбрать другую задачу или завершить приказ решает активное поведение.

## Граница ответственности

```text
ИИ:
  выбирает, что попытаться сделать
  хранит состояние активного поведения
  выдаёт исполняемую задачу
  реагирует на результаты и значимые события

Simulation:
  проверяет возможность выполнения
  изменяет состояние мира
  возвращает результат задачи
  создаёт события о произошедшем
```

Состояние мира является источником истины. Событие только сообщает, что произошло, и заставляет ИИ повторно прочитать нужное состояние.

## Пайплайны

Локальный и глобальный пайплайны сохраняются как оркестраторы `Simulation`.

```text
Input
  → Perception / подготовка сведений
  → AI
  → Movement
  → Interaction
  → Combat
  → Events
  → Snapshot
```

Один и тот же смысл задачи исполняется с разной детализацией:

```text
Локально:
  по тикам активной системы

Глобально:
  укрупнённо за внутриигровой ход
```

Пайплайн не содержит поведение торговли, охраны или боя. Стадия `AI` только продвигает поведения агентов и выдаёт задачи последующим стадиям.

## События

Предпочтительная модель — типизированный буфер событий и входящие сообщения агентов, а не прямые C#-подписки каждого корабля.

```text
Simulation создаёт события текущего шага
  → стадия Events завершает и распределяет их
  → агент получает относящиеся к нему сообщения
  → ИИ читает их в следующей контрольной точке
  → ИИ проверяет актуальное состояние мира
```

Результат задачи и событие мира различаются:

```text
Результат:
  конкретная задача успешно завершилась, завершилась ошибкой,
  была отменена или отклонена; конкретные данные входят в результат

Событие:
  корабль атакован, цель уничтожена, станция исчезла,
  получено критическое повреждение
```

Подробное устройство классов, форматы задач и событий согласуются отдельно до изменения существующего кода.
