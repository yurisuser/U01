# Станции: состав и блоки
Stations.md

## Базовая модель
- **Планеты/луны** — источник ресурсов (депозиты).
- **Стыковка** — только со станциями.
- **Добыча/обитаемость** реализуются станциями на орбите: Orbital Lift / Spaceport.

## Блоки станции (модули)
### MVP (минимальный набор)
- **Dock** — стыковка/очереди/слоты.
- **Cargo** — склад ресурсов.
- **Trade** — покупка/продажа.
- **Power** — энергия и баланс. // под вопросом. может вообще не нужно

- **Logistics** — распределение потоков ресурсов. // под вопросом. может вообще не нужно

## Примеры конфигураций
- **Orbital Lift (добыча)**: Dock + Cargo + Mining
- **Spaceport (обитаемая орбита)**: Dock + Trade + Hab + Repair
- **Пром. станция**: Dock + Cargo + Refinery + Factory

## Замечания по реализации
- **Инвентарь**: общий склад (MVP), модули проверяют свободное место.
- **Док**: слоты/очередь, выдаёт позицию стыковки.
- **Тик**: активная система — по FixedUpdate, оффлайн — батчем за ход.
- **Виртуальный лимит склада**: для каждого товара лимит = `100_000_000 / базовая цена` (из каталога). Деньги на станции не храним — лимит используется для ордеров и ограничений торговли.

## Стыковка кораблей (план реализации)
### Абстрактные варианты
1) **Состояние + Interaction стадия**: ИИ ставит `Docking`, а Interaction на конце хода переносит корабль.
2) **Событийный перенос**: ИИ шлёт `RequestDock`, Interaction обрабатывает очередь в конце хода.
3) **Перенос в AI**: ИИ сам меняет списки, но только в момент конца хода.

Рекомендация: вариант 1 — минимум кода и без гонок.

### Конкретика под текущий код
1) **Ship**: добавить `DockState` (InSystem/Docking/Docked) и `DockTargetStationUid`.
2) **AI**: при достижении координаты станции — скорость = 0, `DockState = Docking`, `DockTargetStationUid = station.Uid`.
3) **Interaction** (`LocalInteractionStage`): на конце хода переносит все `Docking` из `LocalSysRuntimeContext.Ships` в `DockModuleState.Occupied` и ставит `Docked`.
4) **Отстыковка**: обратный перенос (из `Occupied` в системный список) по команде.

## Нечёткий план внутрисекторной торговли
Цель: в населённых секторах появляются станции с разным спросом/предложением, а корабли начинают торговать между ними.

### Шаги (грубый план)
1) **Генерация станций**: при создании галактики добавлять станции в населённые сектора/системы (правила спавна и плотность).
2) **Роли станций**: зафиксировать типы (обычная, добывающая, хаб) и их базовый набор модулей.
3) **Торговые ордера**: описать buy/sell ордера на товары (items), разнести цены и количества между станциями.
4) **Разница в спросе/предложении**: задать распределения (региональные коэффициенты, связь с фракцией/типом станции).
5) **Корабли‑трейдеры**: логика выбора сделки (маржа, расстояние, риск), маршрут A→B→A.
6) **Склад и исполнение**: остатки берём из карго, ордера исполняются, склад обновляется.
7) **Тестовый прогон**: логировать сделки и убедиться, что торговля “дышит”.
