## Заселённые созвездия
- Фракционный конфиг задаётся по созвездию/фракции; если конфиг не найден или короче списка систем, оставляем остаток без изменений.
- Порядок систем для применения конфига: выбираем home как самую внутреннюю систему созвездия с внешним гиперлинком; дальше идём BFS по внутренним линкам, слой за слоем, дальние по числу прыжков в конце.
- Если несколько претендентов на home, тай-брейк: индекс.
- Внутри одного слоя сортируем по длине линка до home, дальше тот же тай-брейк.
- При применении меняем только содержимое системы (звезда и планетные системы), позиции/линки/ConstellationId/OwnerFrac не трогаем, UID планет/лун пересоздаём.
- Черные дыры в созвездии меняем на нормальные звездные системы.

## Архетипы фракций (идея)
- Флаги в JSON (пример: пират, кочевой/оседлый, экспансивный/интровертный, скрытый, вечный враг).
- Мапим флаги на архетип/стратегию спауна (лучше таблица маппинга, чем один класс на флаг, чтобы не взорваться от комбинаций).
- Архетип задаёт набор правил размещения (столица, индустрия, форпосты) и действия (станции, пометки isHome, переименование).
- Нужны приоритеты/запреты для конфликтных флагов (кочевой vs оседлый, интровертный vs экспансивный).
- Параметры архетипов держать в данных, а код — общий пайплайн (сбор фич → скоринг → применение), чтобы баланс правился без переписывания логики.
- Внутри генератора можно сделать «разветвитель» по флагам: набор функций/модификаторов на признаки (Pirate(), Nomad(), Introvert(), etc.), а конвейер для фракции собирается из них по флагам (детерминированный порядок применения и приоритеты для конфликтов обязательны).

## ENUM-признаки фракции. Фракция обладает только одним (EFractionTypes)
- Regular — регулярная фракция: системы, столица, заводы, экономика, оборона.
- Hidden — скрытая фракция: без систем и  столицы.
- Super — сверхсильная фракция: системы, столица, замкнутая на себя, независимая экономика. 
- Enemy — регулярный враг: стандартные системы/столица, враждебность по умолчанию.
- Pirate — пираты: разбросанные базы, без формальной столицы, владеют секторами.
- В fraction.json хранится ключ fractionType (строка), значения — см. EFractionTypes.
- В home.scenario.json/json5 для Regular можно помечать, что имя брать из каталога: `catalogName: true` на звезде/планете/луне (если не задано имя явно — берётся из списка имён фракции по порядку).

## Выбор систем в сценариях (pick)
- Формат:
- `pick` (enum):
    `closest_to_capital` (ближайший к столице),
    `far_to_capital` (удалённейший от столицы),
    `closest_to_hyper_distance` (ближайший к внешним гиперлинкам),
    `far_to_hyper_distance` (удалённейший от внешних гиперлинков),
    `have_external_hyper` (любая с внешним гипером; если выбрали занятую — берём следующую по этим же правилам, пока есть свободные; если систем не осталось — пропуск шага)

## Сила изменений системы (enum)
- `replace` — полностью пересобрать систему: звезда/планеты/луны/станции по сценарию, старое содержимое выкинуть нахуй.
- `merge` — применить сценарий поверх существующего: добавлять/заменять только указанные поля/объекты, остальное оставить как сгенерилось.

## Выбор орбиты (enum) 
(для размещения станции например)
- `closest_empty_to_star` — ближайшая свободная орбита к звезде.
- `closest_empty_to_edge` — ближайшая свободная к краю (максимальный индекс из свободных).
- `closest_empty_to_middle` — ближайшая свободная к середине диапазона орбит.
